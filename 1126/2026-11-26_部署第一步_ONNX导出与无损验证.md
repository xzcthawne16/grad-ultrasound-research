## 二、部署的认知地图（三个贯穿始终的问题）

| 层 | 回答的问题 | 要掌握的东西 |
|----|-----------|-------------|
| 格式层 | 怎么翻译？ | ONNX（torch.onnx.export） |
| 引擎层 | 谁来跑？ | ONNX Runtime（入门）、TensorRT / OpenVINO（进阶） |
| 优化层 | 怎么快又省？ | 量化 FP32→INT8、PTQ / QAT、加速 |

**入口是 ONNX，不是 C++。** ONNX 是「通用语言」，把「研究环境」（PyTorch + Python + GPU）和「设备环境」（C++ / 嵌入式 / 低算力）彻底解耦。

## 三、核心概念（今天亲手验证过的）

### 1. 三个文件的本质区别（最关键）

| 文件 | 存了什么 | 拿到它还需要什么才能用 |
|------|---------|---------------------|
| `.pth`（state_dict） | **只有权重数字** | 还要代码搭骨架（建 ResUNet）再 load_state_dict |
| `.onnx` | **结构 + 权重一起打包** | 什么都不用，推理引擎直接读 |

→ 这就是为什么部署一定要走 ONNX：`.pth` 离不开 Python 代码，`.onnx` 是自包含的。

### 2. 导出 ONNX = 「跑一遍」而非「读权重」

`torch.onnx.export` 需要一个 `dummy` 假输入，让模型**真实前向算一次**，把计算过程记录成静态计算图（结构），再把权重写进去。所以 dummy 必须有，它是「跑一遍」的燃料。

### 3. 验证 = 同一个输入喂两个引擎比误差

| 引擎 | 怎么跑 |
|------|--------|
| PyTorch | `model(x)` |
| ONNX Runtime | `sess.run(["output"], {"input": x})` |

喂同一个 `x`，比两个输出的误差。误差 < 1e-3 说明导出无损。

### 4. 节点名是「约定」，两边必须一致

- `input_names` / `output_names` 在**导出时**定名字
- `sess.run` 里的 `"output"` / `"input"` 在**验证时**必须和导出时一致
- 只改一边不改另一边 → 报错 `Invalid Feed Output Name: output`

## 四、export_onnx.py 结构（四个函数 + 主入口）

1. **导入区**：`from train_residual import ResUNet` —— 定义与使用分离，import 复用模型，不重复写网络。
2. **train_and_save**：训练 + `torch.save(model.state_dict())`。核心四行：`zero_grad → forward → loss → backward → step`。
3. **export_onnx**：`torch.onnx.export(model, dummy, path, input_names, output_names, opset_version=18, do_constant_folding, dynamic_axes=None)`。
4. **verify_onnx**：同输入，PyTorch vs onnxruntime 比误差。
5. **主入口**：`--skip-train` 分支——先 `ResUNet()` 搭骨架，再 `load_state_dict()` 填权重（因为 .pth 只存数字不存结构）。

## 五、踩过的坑（面试可讲）

1. **PowerShell vs Git Bash**：PowerShell 的 `rm` 不接受空格分隔多文件，要用逗号 `rm a, b, c`。看提示符 `PS` = PowerShell，`$` = bash。
2. **onnxscript 缺失**：torch 2.x 的 ONNX 导出器依赖 `onnxscript`，没装会 `ModuleNotFoundError`。
3. **opset_version 过低**：torch 2.x 新导出器要求 `opset_version >= 18`，写 13 会触发版本转换警告（虽不致命但应避免）。
4. **多 Python 环境混淆**：正确环境是 `E:/develop/Graduate_AI/.venv/`（有 torch 2.13 + CUDA）；`E:/develop/python/` 是空的。VS Code 右下角要选对解释器。
