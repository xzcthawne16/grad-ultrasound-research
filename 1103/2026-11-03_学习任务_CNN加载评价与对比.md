### 2.1 先讲清「为什么今天要做加载评价」（没懂就停）

训练循环里 `torch.save(model.state_dict(), ...)` 存的是**一串「层名 → 张量」的参数表**，不是「模型代码」。所以换一个新环境要用它，得做三件事：

1. **把模型结构重新搭出来**（代码里再写一遍 `SmallCNN`，和训练时一模一样）；
2. **把参数表填进去**（`load_state_dict`，按层名严格对号入座，差一个 key 就报错）；
3. **把它当推理模型用**（`eval()` + `no_grad()`）。

「独立」二字的要求：**重启 kernel（或另开一个 .py / 新笔记本）**，从头 `import`，而不是接着 11/2 那个还留在内存里的 `model` 变量往下跑——那样测的是「内存里还在的模型」，不是「盘上存下来的权重」，没有意义。

判据只有一条：**加载后完整评价验证集，val_acc 必须等于 history.json 第 5 轮的 76.60%（val_loss 0.6855）**。对上了，才叫「保存→加载→复用」闭环成立；对不上，先查结构/数据口径/加载参数，别改数字。

from pathlib import Path
import json
import torch
from torch import nn
from torch.utils.data import DataLoader, Subset
from torchvision import datasets, transforms

# 1) 重新定义和训练时一模一样的结构
class SmallCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 8, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Conv2d(8, 16, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
        )
        self.classifier = nn.Sequential(
            nn.Flatten(),
            nn.Linear(16 * 7 * 7, 10),
        )
    def forward(self, x):
        x = self.features(x)
        return self.classifier(x)

# 2) 数据：同一划分、同一预处理；⚠️ 验证集用 train_full（见 §2.0）
data_root = Path(r"E:\develop\Graduate_AI\learning-lab\data")

train_full = datasets.FashionMNIST(data_root, train=True,  download=False, transform=tf)
split = json.loads(Path(r"E:\develop\Graduate_AI\learning-lab\results\day22\split_indices.json").read_text(encoding="utf-8"))
val_set = Subset(train_full, split["val_indices"][:1000])   # ✅ 不是 test_full
val_loader = DataLoader(val_set, batch_size=64, shuffle=False, num_workers=0)

# 3) 独立加载（新进程 / 新 kernel）
run_dir = Path(r"E:\develop\Graduate_AI\learning-lab\results\day1102\20261102_170336")
model = SmallCNN()
state = torch.load(run_dir / "model_weights.pt", map_location="cpu", weights_only=True)
model.load_state_dict(state)      # 按层名严格对号入座；key 对不上会报错
model.eval()

# 4) 自己写 evaluate（11/2 写过：按样本数加权 loss，argmax 数对错）
def evaluate(model, loader):
    model.eval()
    total_loss, correct, n = 0.0, 0, 0
    with torch.no_grad():
        for xb, yb in loader:
            z = model(xb)
            total_loss += nn.functional.cross_entropy(z, yb).item() * yb.size(0)
            correct += (z.argmax(dim=1) == yb).sum().item()
            n += yb.size(0)
    return total_loss / n, correct / n

va_loss, va_acc = evaluate(model, val_loader)
print(f"加载后验证：val_loss={va_loss:.4f}  val_acc={va_acc:.4f}")
# 预期：val_acc ≈ 0.766、val_loss ≈ 0.6855，和 history.json 第 5 轮一致

# 5) predict：抽 3 张验证图，打印 argmax + softmax 概率
class_names = train_full.classes
xb, yb = next(iter(DataLoader(val_set, batch_size=3, shuffle=False, num_workers=0)))
with torch.no_grad():
    prob = model(xb).softmax(dim=1)
    pred = prob.argmax(dim=1)
for i in range(len(yb)):
    print(f"真实 {class_names[yb[i].item()]:<12s} → 预测 {class_names[pred[i].item()]:<12s} 置信度 {prob[i, pred[i]].item():.3f}")

### 2.3 变式：评价结果和 batch 大小无关吗？（先预测再运行）

**先写预测**：把 `val_loader` 的 `batch_size` 从 64 改成 1（或 32），加载同一份权重再评一次，val_acc / val_loss 会变吗？为什么？

然后运行核对（只改 DataLoader 的 batch_size，其余不动）：

```python
for bs in (64, 32, 1):
    loader = DataLoader(val_set, batch_size=bs, shuffle=False, num_workers=0)
    l, a = evaluate(model, loader)
    print(f"batch={bs:>3d}  val_loss={l:.6f}  val_acc={a:.6f}")
```

**预期**：三个数几乎完全一致（浮点末位可能有极小差）。原因：`evaluate` 里 loss 是 `loss * yb.size(0)` 按样本数加权、acc 是 `correct/n` 按样本数平均，**都不按批平均**，所以最后一批是否凑满 64 不影响结果。

> 一句话结论（可进报告/纠偏 #6）：**推理时 batch 大小不改变评价结果**，前提是评价口径是「按样本加权/平均」，而不是「按批简单平均」。这为 11/5 换数据后复用同一个 `evaluate` 打了底。

## 3. 信号：FFT 变式（拉长 T，看格点变密、泄漏变窄）（1–1.5 小时）

### 3.1 回忆 11/2 的结论（一句话）

11/2 做了 2.0Hz vs 2.3Hz：`fs=100、T=1s、N=100`，2.0Hz 落在格点上峰≈1.00，2.3Hz 落在两格之间峰掉到约 0.86、旁边冒出旁瓣——这就是**频谱泄漏**。

### 3.2 变式：把观察时长 T 拉长（先预测再运行）

11/2 留的尾巴是「把 T 拉长会怎样」。今天正式做。唯一变量：**T**；`fs=100、f0=2.3Hz` 不变。

**先预测**（写下来再跑）：T 从 1s 拉到 2s、4s，2.3Hz 的峰是变高还是变矮？旁瓣变宽还是变窄？到多长 T，2.3Hz 会「正好」落在格点上、泄漏消失？

**提示**：格点间隔 `df = fs/N = 100/T`，T 越大格点越密；2.3Hz 落在格点上需要 `2.3 / df` 是整数。

```python
import numpy as np
import matplotlib.pyplot as plt
plt.rcParams["font.sans-serif"] = ["Microsoft YaHei", "SimHei", "DejaVu Sans"]
plt.rcParams["axes.unicode_minus"] = False

fs = 100
f0 = 2.3
for T in (1.0, 2.0, 4.0, 10.0):
    N = int(fs * T)
    t = np.arange(0, T, 1/fs)
    x = np.sin(2*np.pi*f0*t)
    X = np.fft.rfft(x)
    fr = np.fft.rfftfreq(N, d=1/fs)
    a = np.abs(X) * 2 / N
    peak = a.max(); peak_f = fr[a.argmax()]
    print(f"T={T:.0f}s  N={N:>4d}  df={fs/N:.2f}Hz   峰@{peak_f:.2f}Hz  峰值={peak:.3f}")
    plt.plot(fr, a, marker="o", ms=3, label=f"T={T:.0f}s")
plt.xlim(0, 5); plt.xlabel("freq (Hz)"); plt.ylabel("amplitude"); plt.legend()
plt.title("2.3Hz 泄漏随观察时长 T 变窄")
plt.show()
```

**预期方向（以实测为准，别预填）**：
- `T=1s（N=100, df=1Hz）`：2.3 落在 2~3 之间，峰约 0.86，旁瓣明显；
- `T=2s（N=200, df=0.5Hz）`：格点加密一倍，峰更接近 1.0，旁瓣变窄；
- `T=4s（N=400, df=0.25Hz）`：再加密，峰更接近 1.0；
- `T=10s（N=1000, df=0.1Hz）`：`2.3/0.1 = 23` 是整数，2.3Hz **正好落在格点**，且 2.3Hz×10s = 23 个整周期 → **峰高回到 1.00，泄漏消失**。

把这张图存下来（建议存 `learning-lab\results\day1103\leak_vs_T.png`），就是报告 6.1 节「泄漏如何减轻」的证据图。

### 3.3 一句话结论（写进笔记/报告）

**拉长观察时长 T，频率格点变密（df=fs/N 变小），泄漏变窄、峰变高；当信号频率正好落在格点上（且是整周期）时，泄漏消失、峰高回到真实幅值。** 实际工程里这就是「采集更长的数据 / 选合适的采样点数」来对齐频率的思路（加窗是另一条路，11/4 起再说，今天不展开）。

### 3.4 与超声的连接（一句话）

真实超声里「观察时长」对应「一次采集的时间窗长度」：窗口越长，频域分辨率越高、越能分清相邻的两个频率成分（比如谐波和基频），代价是时间分辨率下降——这是通信/信号里最经典的时频折中，超声波束形成、多普勒测速都踩在它上面。
