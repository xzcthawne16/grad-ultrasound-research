## 2. 主任务：小 CNN 训练闭环（3–3.5 小时）

### 2.0 先把「训练」讲成一句人话（没看懂就停）

**训练 = 拿一堆「图 + 正确答案」的配对，反复做五件事。** 每一次五件事叫做 **1 个 step（一步更新）**：

| 步 | 做什么 | 一句话 |
|---|---|---|
| ① 前向 forward | `z = model(xb)` | 把 64 张图送进网络，吐出 64×10 个分数 |
| ② 算损失 loss | `loss = loss_fn(z, yb)` | 把「分数」和「正确答案」比一比，压成**一个数** |
| ③ 清零 zero_grad | `optimizer.zero_grad()` | 把上一步残留的梯度擦掉（梯度会累加，见 §2.2） |
| ④ 反向 backward | `loss.backward()` | 从 loss 倒着算：每个参数「该往哪个方向改、改多少」 |
| ⑤ 更新 step | `optimizer.step()` | 优化器按梯度真的去改参数（改多少由学习率 lr 决定） |

四个必须分清的词：

- **batch（批）**：一次送进网络的样本数，今天仍是 64。为什么不分整批？内存有限，且小批次的梯度带随机性，反而不容易卡住。
- **step（步）**：一次参数更新。5000 张图 ÷ 64 = 78.1 → 每轮 **79 步**（最后一包只有 8 张）。和线性基线完全一致。
- **epoch（轮）**：把所有训练样本过完一遍 = 79 步。今天跑 **5 轮 = 395 次更新**。
- **lr（学习率）**：每步沿梯度走多远。太大→跳过头（loss 乱蹦甚至变 nan）；太小→爬得太慢。

还有两个「模式开关」，今天只要求会用、并知道它们**各自负责什么**：

- `model.train()` / `model.eval()`：切换训练/推理模式。**诚实说明：今天这个小 CNN 只有 Conv / ReLU / MaxPool / Linear，没有 BatchNorm、没有 Dropout，所以 train() 和 eval() 算出来的数一模一样。** 但必须写——一旦以后加了 BN/Dropout，不切换就会得到错误的验证结果。这是习惯，不是今天能看出差别的东西。
- `torch.no_grad()`：不记录梯度，省内存、跑得快，**不改变数值**。它和 `eval()` 是两件不同的事，别混为一谈（一个管"层的行为"，一个管"要不要记梯度"）。

### 2.1 补一个 B 级缺口：交叉熵到底在算什么

分类不用 MSE，用**交叉熵**。三步，全部能手算：

1. **softmax**：把 10 个原始分数（logits）变成 10 个正数、加起来等于 1 的概率：`p_i = exp(z_i) / Σ exp(z_j)`
2. **取出正确类那一项的概率**：`p_correct`
3. **取负对数**：`loss = −ln(p_correct)`

**手算一个 3 类的例子**（写在笔记里，别只跑代码）：

```text
z = [2.0, 1.0, 0.1]，正确答案 = 第 0 类
exp(z) = [7.389, 2.718, 1.105]，和 = 11.212
p = [0.659, 0.242, 0.0986]
loss = −ln(0.659) = 0.417
```

直觉：**预测越自信且越对 → loss 越接近 0；越自信但答错 → loss 越大（趋向无穷）。** 所以 loss 下降＝模型在变好，这是后面看曲线的唯一依据。

程序核对（预期 0.4173 左右）：

```python
import torch
from torch import nn

z = torch.tensor([[2.0, 1.0, 0.1]])   # 1 个样本、3 类的分数
y = torch.tensor([0])                  # 正确答案是第 0 类
print(nn.CrossEntropyLoss()(z, y))
```

⚠️ **最常踩的坑**：`nn.CrossEntropyLoss()` **内部自己做 softmax**，所以喂进去的必须是**没归一化的原始 logits**。如果先自己套一层 `softmax` 再传进去，等于做了两遍，loss 会一直很高而你还以为模型不行。同样地，**评价时也直接把 logits 交给它，不要先 softmax**；要算概率或画图时才单独 softmax。

### 2.2 为什么要 `zero_grad()`：梯度默认是累加的

不讲原理只记口诀会忘，做个 3 行的实验就懂：

```python
w = torch.tensor([1.0], requires_grad=True)
for i in range(2):
    loss = (w ** 2).sum()      # dloss/dw = 2w，w=1 时是 2
    loss.backward()
    print(f"第{i+1}次 backward 后 w.grad = {w.grad.item()}")
# 预期输出：2.0，然后 4.0
```

第一次梯度是 2，第二次应该是 2，可**实际打印 4**——因为 PyTorch 默认把新梯度**加到** `.grad` 上（累加）。后果：第二步用的其实是「两次梯度之和」，等于学习率悄悄翻倍，训练轨迹完全不是你设定的那个。

所以规范顺序永远是：**先 `zero_grad()`，再 `backward()`，最后 `step()`**。顺序写反了今天可能也"能跑"，但你会得到一个解释不了的结果。

### 2.4 自己写 `evaluate()`（第一项「自己写」，先写再看参考）

写不出来再看参考：

```python
def evaluate(model, loader, loss_fn):
    """返回 (平均loss, 准确率)。注意：只算不更新。"""
    model.eval()
    total_loss, correct, n = 0.0, 0, 0
    with torch.no_grad():
        for xb, yb in loader:
            z = model(xb)
            total_loss += loss_fn(z, yb).item() * yb.size(0)   # 按样本数加权
```

两个容易错的点：`loss_fn(...).item() * yb.size(0)` 要**乘批量大小**再累加（最后一批不是 64 张，直接平均会偏）；`argmax(dim=1)` 是**沿着"类别"那一维**取最大值（`[64,10] → [64]`），写 `dim=0` 就错了。

### 2.6 第 2 步：跑 1 个 epoch，先计时再决定

**第二项「自己写」**：`train_one_epoch()`。照 §2.0 的五步表自己写，写完再对照下面参考（10 行左右，写不出来说明五步还没记牢）：

```python
def train_one_epoch(model, loader, loss_fn, optimizer):
    model.train()
    total_loss, correct, n = 0.0, 0, 0
    for xb, yb in loader:
        z = model(xb)                 # ① 前向
        loss = loss_fn(z, yb)         # ② 算损失
        optimizer.zero_grad()         # ③ 清零
        loss.backward()               # ④ 反向
        optimizer.step()              # ⑤ 更新
        total_loss += loss.item() * yb.size(0)
        correct += (z.argmax(dim=1) == yb).sum().item()
        n += yb.size(0)
    return total_loss / n, correct / n
```

## 3. 信号：幅值换算正式讲＋两频变式＋泄漏预习（1–1.5 小时）

### 3.1 把 11/1 那个「×2/N」讲清楚

11/1 你已经在用 `amp = |X| * 2 / N`，但当时是"先记住"。今天补上道理：

`rfft` 算的是 `X[k] = Σ x[n]·e^(−j2πkn/N)`。对一个**幅值为 A 的正弦**，它在一个完整周期里的正负两半各贡献一份，所以 `|X[k]| = A·N/2`。反过来：

```text
A = 2·|X[k]| / N        （适用于 0 < k < N/2 的格子，也就是"真正的振动频率"）
```

两个例外，**不能**乘 2：

- **k = 0（直流分量）**：它代表"整段信号的平均电平"，没有正负抵消，`A = |X[0]| / N`；
- **k = N/2（奈奎斯特）**：它是采样极限上的那个频率，本身不成"一对"，同样 `A = |X[k]| / N`。

验证一下（加一个 0.5 的直流偏置，看 0Hz 峰是否按 /N 算得到 0.5）：

```python
import numpy as np
fs, T = 100, 1.0
t = np.arange(int(fs*T)) / fs
x = 0.5 + np.sin(2*np.pi*2*t)          # 直流 0.5 + 2Hz 幅值 1
X = np.fft.rfft(x); f = np.fft.rfftfreq(len(x), d=1/fs); N = len(x)
print("0Hz :", f[0],  "|X|/N =", np.abs(X[0])/N)        # 预期 ≈ 0.5
i = int(np.argmax(np.abs(X)[1:])) + 1                   # 跳过直流
print("峰  :", f[i],  "2|X|/N =", 2*np.abs(X[i])/N)      # 预期 2.0 Hz、≈1.0
```

### 3.2 手算一组小 DFT（4 点，能手算完就对得上）

`fs=4`，信号 `x = [0, 1, 0, −1]`。先看它是什么：`t = 0, 0.25, 0.5, 0.75` 上的 `sin(2π·1·t)`，正好是 **1Hz、1 个整周期**。

手算 `k=1` 这一格：`X[1] = Σ x[n]·e^(−j2πn/4) = 0 + 1·e^(−jπ/2) + 0 + (−1)·e^(−j3π/2)`

- `e^(−jπ/2) = −j`（可以理解成"顺时针转 90°"，`j` 只是用来记方向的两个数）
- `e^(−j3π/2) = +j`
- 所以 `X[1] = −j + (−1)(j) = −2j`，`|X[1]| = 2`
- 幅值 `A = 2·2/4 = 1` ✓ 与我们设的 sin 幅值 1 一致

程序核对：

```python
x4 = np.array([0., 1., 0., -1.])
X4 = np.fft.rfft(x4)
print(np.abs(X4), np.fft.rfftfreq(4, d=1/4))            # |X|: [0, 2, 0]
print("A(1Hz) =", 2*np.abs(X4[1])/4)                     # 预期 1.0
```

> 复数那一段看不懂就跳过：**只要求你能说出"幅值＝2|X|/N，原因是正弦被拆成一对"**，手算那两行等以后学了复数再补。

### 3.4 泄漏：为什么「不是整周期」会出事

**定义（人话）**：FFT 的频率轴是一条条**格点**（间隔 `fs/N`）。当信号的真实频率**正好落在格点上**，能量就集中在一格里；**落在两格之间**时，能量被"摊"到邻近好几格，峰变矮、变宽，旁边还会冒出小峰。这个现象叫**频谱泄漏**。

类比：拿一把刻度是 1Hz 的尺子去量 2.3Hz 的东西，你只能报"2 或 3"，误差就散到邻居那儿去了。

**对比实验**（唯一变量：频率 2.3Hz；fs=100、T=1s、N=100 不变）：

```python
for f0 in (2.0, 2.3):
    t = np.arange(0, 1.0, 1/100)
    x = np.sin(2*np.pi*f0*t)
    X = np.fft.rfft(x); fr = np.fft.rfftfreq(len(x), d=1/100)
    a = np.abs(X) * 2 / len(x)
    top = np.argsort(a)[-4:][::-1]
    print(f"f0={f0}Hz →", [(round(fr[i],1), round(a[i],2)) for i in top])
```

**预期**：2.0Hz 时只有一个 ≈1.00 的峰；2.3Hz 时最大峰掉到 **0.8–0.9 附近**（约 0.86，作参考，以实测为准），并且 2Hz、3Hz 都会冒出旁瓣。**画两张频谱放一起**（或叠在一张图上），这就是报告 6.1 节「泄漏」的证据图。

**顺带回答一个常被问的问题**：把 T 拉长（N 变大）会怎样？→ 格点变密（分辨率变好），泄漏变窄，但**只要频率不在格点上，泄漏就不会消失**。这个"变密"的演示留到 11/3 做（今天只做 1s 这一组）。

### 3.5 与超声的连接（一句话，写进报告 6.3）

`RF 原始信号 → 波束形成(DAS) → 包络 → 对数压缩 → B 模式图`。FFT 在这条链上属于"看信号里有什么频率成分"的工具（发射频率、谐波、噪声落在哪一段）；滤波（11/4 起）则是"把不想要的频段去掉"。**两者都不是直接出图的那一步，但决定了图干不干净。**
